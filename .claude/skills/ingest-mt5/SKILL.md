# Ingest MT5

Домен превращения сырых deals из терминала MetaTrader 5 в позиции журнала. Самая рискованная часть продукта: ошибка здесь тихо портит цифры пользователя и обнаруживается через недели.

## Load First

- `SPEC.md` §6 (нормализация: маппинги, время, символы) и §7 (сборщик позиций) — **дословно, это эталон**.
- `SPEC.md` §3.3 (таблицы `deals`, `positions`, `open_positions`, `sync_runs`) и §5.3 (контракт `/ingest`).
- `packages/shared-schemas/ingest-deals.schema.json` — контракт батча.
- `docs/fixtures.md` — что описывает каждая фикстура (появляется в `S1-03`).
- Для задач коллектора дополнительно `SPEC.md` §8.

## Own

`apps/api/app/domains/ingest/**` (`normalizer.py`, `position_builder.py`, `router.py`, `schemas.py`), `apps/api/tests/fixtures/deals/**`, `packages/shared-schemas/ingest-deals.schema.json`, часть `apps/collector-mt5/collector/` в части формирования батча.

## Domain Rules

1. **`deals` — append-only.** Факты брокера не обновляются и не удаляются. Дедупликация — по естественному ключу `(account_id, deal_ticket)`, не «уже есть → ошибка».
2. **Перекрытие батчей — норма, а не сбой.** Коллектор намеренно перезапрашивает окно (`last_sync_at − 24h`). Повторный батч обязан давать тот же результат. Идемпотентность — не оптимизация, а требование с тестом.
3. **`position_builder` — чистая функция.** Никакого I/O. Вход: все deals по `(account_id, position_id)`, отсортированные по `(time_utc, deal_ticket)`, плюс необязательная запись `open_positions`. Выход: одна строка `positions`.
4. **UPSERT по `(account_id, position_id)` сохраняет `positions.id`.** На нём висит пользовательский слой (`journal_entries`, `reflections`, `attachments`). Пересборка, которая пересоздаёт `positions.id`, уничтожает записи пользователя — это blocker, а не оптимизация.
5. **Хеджинг и неттинг обрабатываются одинаково:** `position_id` в MT5 уникален в обоих режимах. Единственное отличие — `inout` на неттинге.
6. **`inout` на неттинге в v1: позиция закрывается, остаток новую позицию НЕ создаёт.** MT5 при перевороте назначает новый `position_id`, новая позиция придёт своими deals. Тест на это обязателен.
7. **`balance`, `credit`, `other` не участвуют в сборке позиций** — кроме `other` с `position_id ≠ 0`: его `profit/commission/swap/fee` прибавляются к позиции. Сохраняются в `deals` все, для сверки баланса.
8. **Время терминала — не UTC.** `datetime.fromtimestamp(deal.time, tz=UTC)` даёт «фальшивый UTC», равный серверному времени брокера. Трактуем как `time_server`. `time_utc = time_server − offset`, где offset присылает коллектор в батче. Храним оба.
9. **Смещение не пересчитывает прошлое.** При смене offset (DST) уже сохранённые deals не пересчитываются — они уже в UTC. Смещение батча пишется в `sync_runs`.
10. **`net_pnl = gross_pnl + commission + swap + fee`**, где `gross_pnl = Σ profit` по всем deals позиции, включая `other` с этим `position_id`. Всё в `numeric`, никакого float.
11. **`status = 'closed'`** при `|opened − closed| < 1e-8` **и** отсутствии записи в `open_positions`. Одного условия недостаточно.
12. **Лимит батча — 5000 deals**, больше → `413`.
13. **`source='user'` в словаре символов не перезаписывается автоматикой.** Ручная правка пользователя переживает синк.
14. **Фикстуры обезличены:** `login` заменён, `comment` очищен. Реальный логин или пароль в фикстуре — blocker.

## Workflow

**Порядок работы над сборщиком:** сначала фикстура, потом код. Фикстура описывает реальный кейс из выгрузки, а не придуманный.

Обязательные фикстуры (`SPEC.md` §7) — все восемь должны проходить:

1. простая long-сделка;
2. short с SL;
3. частичное закрытие в 3 приёма (взвешенный `avg_exit`);
4. доливка + закрытие;
5. переворот на неттинге (`inout`);
6. позиция с корректировкой `other`;
7. открытая позиция без выхода;
8. deals в двух батчах с перекрытием.

**Обязательные свойства, проверяемые тестом, а не глазами:**

- двойной прогон на тех же deals даёт идентичную строку `positions`;
- два батча с перекрытием не создают дублей `deals` и дают те же позиции, что один общий батч;
- пользовательский слой переживает пересборку (создать рефлексию → пересобрать → рефлексия на месте).

**Порядок проверок:** unit сборщика и нормализатора → интеграционный тест `/ingest/deals` с Postgres (testcontainers) → `mypy --strict` для `domains/ingest` → полный сьют. Покрытие `ingest` — 90 %.

**Сверка с реальностью (`S1-12`):** Σ `net_pnl` закрытых позиций должна сходиться с Σ `profit + commission + swap + fee` по deals счёта и с отчётом терминала. Расхождение 0,00 — критерий, а не пожелание.

## Ask First

- Изменение `ingest-deals.schema.json` — контракт трёх сторон: API, коллектор, тест соответствия. Меняется синхронно или не меняется.
- Любое отступление от алгоритма `SPEC.md` §7 — сначала ADR, потом код. Если алгоритм не покрывает встреченный реальный кейс — это находка и развилка для принципала, а не повод дописать ветку молча.
- Расхождение фикстуры с реальной выгрузкой брокера — стоп: сначала выясняем, что правда, потом правим.
- Изменение семантики `deal_type`/`entry`/`reason` маппингов.
