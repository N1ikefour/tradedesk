# CLAUDE.md — манифест проекта TradeDesk

Правила для AI‑ассистентов в этом репозитории.

**Разделение документов:** `DEVELOPER_MANUAL.md` описывает **как мы работаем** (процесс, роли, ревью, релизы) и не привязан к проекту. Этот файл описывает **проект**: стек, границы, конвенции, DoD. `docs/WORKFLOW.md` — проектная настройка процесса (трекер, ветки, worktree).

Продукт: журнал сделок с автосинком из MetaTrader 5, дашборд, аналитика. Рабочее название — TradeDesk.

## 2. Стек и границы

- **Backend:** Python 3.12, FastAPI, async SQLAlchemy 2, Alembic, arq.
- **Frontend:** Vite + React 19 + TypeScript, TanStack Query/Table, Tailwind, shadcn/ui.
- **Коллектор:** Python + `MetaTrader5`, только Windows, вне Docker, синхронный код.
- Список разрешённых зависимостей — `SPEC.md` §2.3. Новая зависимость — только с обоснованием в PR.
- Все счета в USD (v1). Всё время в БД — UTC `timestamptz`. Деньги — `numeric(18,2)`, цены и объёмы — `numeric(18,8)`.
- Пользователь имеет много счетов; любой пользовательский список принимает `account_ids`. Никогда не привязывай сделки/позиции/рефлексии к `user_id` напрямую.
- `deals` — append‑only факты брокера. `positions` пересобираются из deals. Пользовательский слой (`journal_entries`, `reflections`, `attachments`) никогда не затирается пересборкой.

## 4. Команды

```
make init      # .env из .env.example с генерацией секретов
make up        # docker compose --profile local up -d
make down
make test      # pytest (api) + vitest (web)
make lint      # ruff + mypy + eslint + prettier --check
make migrate   # alembic upgrade head внутри контейнера api
make revision m="описание"   # новая миграция
make types     # openapi → apps/web/src/api/schema.d.ts
```

Коллектор: `cd apps/collector-mt5 && run-collector.bat` (Windows).

**Статус:** ни одна команда пока не существует — `Makefile` создаётся в S0‑01. До этого проверки запускаются напрямую, и это указывается в итоге явно.

## 5. Правила кода

- **Python:** `ruff` (line‑length 100), типы везде, `mypy --strict` для `domains/ingest` и `domains/analytics`. Async в API; в коллекторе — синхронный код.
- **TypeScript:** strict, `any` запрещён; импорты через `@/`; строки UI только в `src/i18n/ru.ts`.
- **API:** префикс `/api/v1`, snake_case, ошибки в формате `SPEC.md` §5.1 (`{"error": {"code", "message", "details"}}`), курсорная пагинация, время ISO 8601 с `Z`.
- **Валидация — на границе API один раз**, pydantic v2. Внутри системы повторно не валидировать.
- **Миграции** только вперёд‑совместимые (`SPEC.md` §11.4): новые колонки nullable или с default; переименование — добавление + backfill + удаление в следующем релизе.
- **Комментарии — «почему», не «что».** Комментарии‑отчёты о проделанной работе запрещены. Длинные объяснения — в `docs/`.
- **Секреты, пароли, токены** — никогда в логах, фикстурах, тестах, коде. Фикстуры deals — обезличенные. Пароль счёта читается только эндпоинтом `GET /internal/collector/assignments` и никогда не возвращается в пользовательский API.
- Не трогай `packages/shared-schemas/ingest-deals.schema.json` без синхронного обновления pydantic‑моделей, коллектора и теста соответствия.

## 6. Тесты

Обязательны для: `normalizer.py`, `position_builder.py` (фикстуры `tests/fixtures/deals`), идемпотентности `/ingest/deals`, auth‑потока, формул `analytics/metrics.py`.

- Интеграционные тесты — через testcontainers (Postgres, minio). Не мокай базу там, где тестируется SQL.
- Тестовая БД защищена guard'ом: имя обязано содержать `_test`; guard кидает исключение до первого запроса.
- Порог покрытия `ingest` и `analytics` — 90 %.
- Новый код‑путь = тест. Нет теста — явное «почему нет» в итоге.
- Перед PR: `make lint && make test` зелёные.

## 7. Definition of Done

Адаптация `DEVELOPER_MANUAL.md` §6.4 под этот стек. Неприменимый пункт помечается явно, не пропускается молча.

- [ ] Код написан, типы строгие; нет `any` (TS), нет необоснованного `Any` (Python).
- [ ] Валидация pydantic на границе для новых/изменённых эндпоинтов.
- [ ] `make lint` и `make test` зелёные (или явно — что именно гонялось вместо них и почему).
- [ ] Для нового кода есть тесты или явно сказано, почему нет.
- [ ] При изменении схемы — миграция создана, `upgrade head` и `downgrade` проверены; при изменении API — `make types` перегенерирован.
- [ ] UI‑изменения проверены в браузере (или явное «в браузере не проверял»).
- [ ] Секреты не попали в код, логи, фикстуры, вывод команд.
- [ ] Никаких комментариев «что сделано» в коде.
- [ ] Дифф содержит только файлы задачи.

## 8. Ask first — остановиться и спросить

Проектное дополнение к `DEVELOPER_MANUAL.md` §3.2:

- Изменение зафиксированного в `SPEC.md` решения — сначала предложение текстом или `docs/adr/NNNN-<slug>.md`, потом код. Молча не менять.
- Новая зависимость вне `SPEC.md` §2.3.
- Изменение схемы ответа существующего эндпоинта — фронт генерирует типы из OpenAPI.
- Изменение `ingest-deals.schema.json`, инвариантов `deals`/`positions`, auth‑флоу.
- Смена схемы шифрования credentials или ротация `MASTER_KEY` на данных.
- Деструктивные операции против не‑тестовой БД — сначала показать SQL.
- Рефакторинги >2 файлов, не связанные с текущей задачей.

## 9. Чего не делать

- Не менять схему ответа существующего эндпоинта без версии/обсуждения.
- Не добавлять конвертацию валют, мультиязычность, биллинг, Macro Desk — это поздние этапы `PLAN.md`.
- Не запускать коллектор внутри Docker и не пытаться заставить `MetaTrader5` работать на Linux/macOS.
- Не писать длинные комментарии‑эссе в коде; объяснения — в `docs/`.
- Не мержить PR и не переводить тикет в Done — это принципал.
- Не деплоить, не рестартовать, не менять env и конфиги прода без отдельного явного «да» на каждое действие.
