# SETUP — установка и запуск TradeDesk

Инструкция доводит до рабочего приложения в браузере и до первого входа. Читать другие
файлы проекта для этого не нужно.

> **Это черновик для разработчика.** Он прогнан целиком на macOS (Docker 29.6.1,
> Compose v5.3.0). Windows-путь описан, но на Windows **не проверялся** — такие места
> помечены плашкой «⚠️ На Windows не проверено». Дальше по этому тексту две разные
> задачи: `T-06` — прогон инструкции на чистой Windows-машине, `T-01` — финальная
> версия для не-разработчика со скриншотами, которую пишут уже по итогам прогона.

Шагов семь. Сколько уйдёт времени — зависит почти целиком от того, как быстро
скачаются образы Docker на первом запуске; на чистой машине мы этого не мерили.

---

## Что вы получите

Приложение в браузере на `http://localhost:5173` и вход в него по коду. Всё крутится
у вас на машине: наружу ничего не смотрит, регистрироваться нигде не нужно.

Чего вы **не** получите на этом шаге: сделок из MetaTrader 5. Программа-сборщик, которая
их забирает, ставится отдельно и только на Windows — это не входит в эту инструкцию.

## 1. Что нужно на машине

Ставить Python, Node и базу данных **не нужно** — они запускаются внутри Docker.

| Что | Зачем | Как проверить |
|---|---|---|
| **Docker Desktop** | в нём работает всё приложение | `docker --version` и `docker compose version` |
| **Git for Windows** — только на Windows | не для скачивания: он приносит `bash` и `openssl`, без которых не отработают шаги 3 и 4 | `bash --version` в Git Bash |

Проект скачивается **архивом**, поэтому Git как таковой не нужен: на macOS и Linux не
нужен вовсе, на Windows нужен ровно как источник `bash` и `openssl` для скриптов запуска.
Это временно и уже записано отдельной задачей (`X-17`).

Проверено на Docker 29.6.1 с Docker Compose v5.3.0. Нужен Docker Compose **версии 2 или
новее** (команда пишется `docker compose`, через пробел, а не `docker-compose`). Более
старые версии мы не проверяли.

**Место на диске.** Замерено после установки: образы — около 1 ГБ, данные и зависимости —
около 320 МБ. С кэшем сборки закладывайте **3 ГБ свободного места**.

**Память.** Пять контейнеров в покое занимают около 310 МБ, из них планировщик фоновых
задач — около 60 МБ. На машине с 16 ГБ этого не заметно; Docker Desktop сверх того
резервирует несколько гигабайт под свою виртуальную машину.

Места на диске планировщик не добавляет: он работает на том же образе, что и сервер
приложения, — второй образ состоит из тех же слоёв и занимает не диск, а только имя.

### Чем запускать команды

Команды ниже показаны в двух видах: короткие `make …` и длинные `sh infra/scripts/…`.
Делают они **одно и то же** — `make` просто вызывает те же скрипты.

- **macOS:** `make` приходит с Command Line Tools. Если `make --version` ругается —
  выполните `xcode-select --install`.
- **Linux:** `make` обычно уже стоит; если нет — поставьте пакет `make`.
- **Windows:** `make` в системе нет. Смотрите блок ниже.

### ⚠️ На Windows не проверено

> Всё в этом блоке написано по устройству проекта и по документации Docker, но
> **на Windows-машине не прогонялось** — разработка идёт на macOS. Считайте это
> обоснованным предположением, а не проверенным фактом. Проверка на чистой
> Windows-машине — задача `T-06`.

1. **Docker Desktop for Windows** требует включённого **WSL2**. Установщик Docker
   предлагает его включить сам; после этого нужна перезагрузка.
2. **Git for Windows** (<https://git-scm.com/download/win>). Скачивать проект им не нужно —
   нужен «Git Bash» с `bash`, `sh` и `openssl`: на них написаны скрипты запуска, и без
   них шаг 3 работать не будет.
3. `make` на Windows нет. Поэтому:
   - все команды выполняйте **в Git Bash** (правая кнопка в папке проекта →
     «Open Git Bash here»), в варианте `sh infra/scripts/…`;
   - запуск и остановка вдобавок есть файлами: `infra\scripts\start.bat` и
     `infra\scripts\stop.bat` — их можно запустить двойным щелчком. Они внутри
     вызывают те же скрипты через bash из Git for Windows.
   - Файла `init.bat` **нет**: шаг 3 (создание `.env`) на Windows выполняется только
     из Git Bash.

## 2. Скачать проект

Проект приезжает одним архивом со страницы релизов — клонировать репозиторий не нужно.

1. Откройте <https://github.com/N1ikefour/tradedesk/releases>.
2. В самом верхнем релизе, в разделе **Assets**, скачайте `tradedesk-<версия>.zip`.
3. Распакуйте архив в отдельную папку — например в `C:\TradeDesk` или `~/TradeDesk`.

> Репозиторий закрытый, поэтому страница релизов открывается только под аккаунтом
> GitHub, которому выдан доступ. Если страница отвечает «404» — вы либо не вошли в
> GitHub, либо доступа ещё нет.

Внутри архива **один каталог** `tradedesk-<версия>` — в нём и лежит проект. Все
дальнейшие команды выполняются из него:

```bash
cd tradedesk-0.1.0        # подставьте свою версию
```

Windows-распаковщик по умолчанию создаёт папку с именем архива, и получается
`tradedesk-0.1.0\tradedesk-0.1.0` — это нормально, работать нужно во **вложенной**:
в ней лежат `docker-compose.yml` и `SETUP.md`.

### Проверить, что файл скачался целиком (необязательно)

Рядом с архивом на странице релиза лежит `tradedesk-<версия>.zip.sha256` — контрольная
сумма. Оборванная загрузка иначе проявится непонятной ошибкой на сборке.

```bash
shasum -a 256 -c tradedesk-0.1.0.zip.sha256   # macOS и Linux, ожидается «OK»
certutil -hashfile tradedesk-0.1.0.zip SHA256 # Windows: сверить строку глазами
```

### ⚠️ На Windows не проверено

> Windows помечает всё скачанное из интернета, и эта пометка переходит на файлы,
> распакованные встроенным распаковщиком. Из-за неё запуск `start.bat` на шаге 4 может
> упереться в предупреждение SmartScreen. **Мы этого не наблюдали** — Windows-машины у
> нас нет, и утверждать, что шаг нужен, мы не станем.
>
> Если предупреждение появится: правой кнопкой по **скачанному zip** → «Свойства» →
> галочка «Разблокировать» → «Применить», и только потом распаковывать. Проверка этого
> места — часть прогона `T-06`, и в финальную инструкцию (`T-01`) оно попадёт со
> скриншотом или не попадёт вовсе.

## 3. Создать файл настроек

```bash
make init
```

Windows (Git Bash) или машина без `make`:

```bash
sh infra/scripts/init-env.sh
```

Команда создаёт файл `.env` в корне проекта: берёт шаблон `.env.example` и подставляет
в него сгенерированные пароли и ключи. В репозиторий `.env` не попадает — он в
`.gitignore`, и это правильно.

Вывод должен быть таким:

```
Создан /path/to/tradedesk/.env (права 600). Секреты сгенерированы, плейсхолдеры заменены.

⚠️  MASTER_KEY шифрует пароли брокерских счетов. Потеря ключа необратима —
    сохраните .env вместе с резервными копиями базы, иначе дамп бесполезен.

Дальше: make up
```

### ⚠️ Файл `.env` терять нельзя

Внутри `.env` лежит `MASTER_KEY` — ключ, которым шифруются пароли ваших брокерских
счетов в базе. Он существует в единственном экземпляре и нигде больше не хранится.

- Потеряли `.env` — пароли счетов из базы **не восстановить ничем**. Резервная копия
  базы без этого ключа бесполезна: в ней лежат зашифрованные строки, а ключа нет.
- Поэтому храните копию `.env` там же, где будете хранить резервные копии базы.
- Повторный `make init` **ничего не перезаписывает**: если `.env` уже есть, команда
  откажется работать и объяснит почему. Это защита, а не ошибка.

Менять `MASTER_KEY` руками не нужно. Остальные значения в `.env` тоже трогать не надо —
кроме портов, если понадобится (см. «Если порт занят»).

## 4. Запустить

Убедитесь, что Docker Desktop запущен (значок кита в трее/меню-баре), и выполните:

```bash
make up
```

Windows (Git Bash) или машина без `make`:

```bash
sh infra/scripts/start.sh
```

На Windows то же самое делает двойной щелчок по `infra\scripts\start.bat`
(⚠️ на Windows не проверено).

**Что происходит.** Поднимаются пять контейнеров: база данных PostgreSQL, Redis,
сервер приложения, планировщик фоновых задач и веб-интерфейс. Сервер при старте сам
приводит структуру базы в актуальный вид — отдельной команды для этого нет.

Планировщик — это то, что следит за временем без вас. Раз в минуту он проверяет, давно ли
выходил на связь коллектор каждого счёта, и если тот молчит дольше пяти минут, переводит
счёт в «требует внимания». Наружу планировщик ничего не отдаёт, своей страницы у него нет,
и в обычной работе вы о нём не вспоминаете.

**Сколько ждать.** Первый запуск дольше остальных: скачиваются образы (около 1 ГБ),
собирается образ сервера, ставятся зависимости веб-части.

На нашей машине запуск «с нуля» — пустая база, пустые зависимости — занял 40 секунд,
но образы там уже были скачаны, а сборка бралась из кэша. **На по-настоящему чистой
машине будет заметно дольше**: добавьте скачивание около 1 ГБ и первую сборку образа
сервера. Сколько именно это займёт, мы не мерили и придумывать не будем. Повторные
запуски — 15–35 секунд.

Команда ждёт, пока все пять контейнеров действительно станут рабочими, и только потом
печатает адреса. Если что-то не поднялось — она покажет последние строки лога и
завершится с ошибкой, а не соврёт про успех.

Какая версия у вас установлена, показывает <http://localhost:8000/api/v1/version> — это
тот же номер, что стоит в имени скачанного архива и в файле `VERSION` рядом с
`docker-compose.yml`. Он пригодится, если что-то придётся чинить вместе.

Успешный вывод:

```
TradeDesk поднят (профиль local).

  Приложение   http://localhost:5173
  API          http://localhost:8000/api/v1/health
  Документация http://localhost:8000/api/v1/docs

Код для входа писем не шлёт: он лежит на странице
  http://localhost:8000/api/v1/dev/outbox
Искать его в логах не нужно — в логи код не попадает никогда.

Остановить: make down
```

## 5. Войти

### Письма никуда не отправляются — не ждите их

Почта к приложению не подключена. Код для входа **не придёт ни на какой адрес**. Он
кладётся на локальную страницу «Письма (dev)», которая живёт только у вас на машине.

Адрес почты при входе можно указать любой, даже несуществующий: аккаунт заводится по
первому входу. Например, `me@example.com`.

### Порядок

1. Откройте <http://localhost:5173>. Появится экран «Вход».
2. **Откройте вторую вкладку браузера** на <http://localhost:5173/dev/outbox> —
   это и есть страница «Письма (dev)».

   > Вторая вкладка нужна не для красоты. Если уйти со страницы входа на письма и
   > вернуться назад, форма сбрасывается на первый шаг и код придётся запрашивать
   > заново. Проверено — так и происходит.

3. Вернитесь на первую вкладку, введите адрес почты и нажмите «Получить код».
4. Переключитесь на вкладку с письмами и нажмите «Обновить». Самое верхнее письмо —
   ваше. В нём строка вида «Код для входа в TradeDesk: 123456».
5. Вернитесь на первую вкладку и введите код. Форма отправляется сама, как только
   набраны шесть цифр, — кнопку «Войти» нажимать не обязательно.

Код действует 10 минут и годится на один вход. Запросили несколько раз — берите
**самый верхний** код в списке.

Вы попадёте на экран «Дашборд». Слева вверху появится меню, справа — ваш адрес почты
и кнопка «Выйти». Это и есть успешная установка. Страница «Письма (dev)» после входа
есть и в самом меню — вторая вкладка нужна только на время входа.

Если вам удобнее без браузера, тот же список писем отдаёт
<http://localhost:8000/api/v1/dev/outbox> — там же, но в виде JSON. Именно этот адрес
печатает `make up`.

## 6. Что уже работает, а чего ещё нет

Проект на раннем этапе. Меню полное, но за большинством пунктов пока заглушки.

**Работает:**

- вход по коду и выход;
- **Настройки** — экран открывается и даёт задать имя, часовой пояс и час начала
  торгового дня (сохранение мы в этом прогоне не проверяли);
- переключение тёмной и светлой темы;
- страница «Письма (dev)».

**Ещё не работает — открывается страница с надписью «Экран появится в одной из
следующих задач»:**

- Дашборд;
- Журнал и карточка позиции;
- Календарь;
- Счета (и переключатель счетов в шапке — там пока подпись-заглушка).

**Синхронизации с MetaTrader 5 нет.** Программа-сборщик, которая забирает сделки из
терминала, в этот запуск не входит: она работает только на Windows и ставится отдельно.
Поэтому сделок в приложении сейчас взяться неоткуда — это не поломка установки.

## 7. Остановить и запустить снова

```bash
make down
```

Windows (Git Bash) или машина без `make`:

```bash
sh infra/scripts/stop.sh
```

На Windows то же самое делает `infra\scripts\stop.bat` (⚠️ на Windows не проверено).

Команда гасит только контейнеры TradeDesk; чужие контейнеры на машине она не трогает.

**Данные остаются.** База живёт в отдельном хранилище Docker, которое остановка не
удаляет. Проверено: после `make down` и повторного `make up` пользователь и его сессия
остались на месте — браузер даже не попросил войти заново.

Чтобы запустить снова — тот же `make up`. Повторный запуск ничего не ломает: команду
можно выполнять сколько угодно раз.

## Если порт занят

Единственная неполадка, с которой мы столкнулись лично. TradeDesk занимает четыре порта
на `127.0.0.1`: **5173** (приложение), **8000** (сервер), **5432** (база), **6379**
(Redis). Если какой-то из них уже держит другая программа, запуск остановится:

```
Error response from daemon: ... Bind for 0.0.0.0:5432 failed: port is already allocated

Порт занят другой программой. TradeDesk слушает 5173 (web), 8000 (api),
5432 (postgres), 6379 (redis) — всё на 127.0.0.1.
Освободи порт или задай другой в .env: WEB_PORT, API_PORT, POSTGRES_PORT, REDIS_PORT.
```

У нас на 5432 сидел PostgreSQL от соседнего проекта — это самый частый случай. Так же
легко занимается 6379: Redis есть почти в каждом проекте.

**Как починить.** Откройте `.env` и найдите закомментированный блок под строкой
`# Порты на хосте` — ближе к концу файла, сразу после `DOMAIN=`:

```
#WEB_PORT=5173
#API_PORT=8000
#POSTGRES_PORT=5432
#REDIS_PORT=6379
```

Уберите `#` у нужной строки и поставьте другой номер — например `POSTGRES_PORT=5433`.
Сохраните файл и повторите `make up`.

Если меняете `WEB_PORT`, поправьте в том же `.env` и строку `APP_URL=http://localhost:5173`
на новый номер: это единственное место, где адрес приложения записан явно, и держать там
неверный незачем. На работу приложения расхождение сейчас не влияет — по коду `APP_URL`
читает одна проверка, источника запросов, и она вдобавок разрешает тот адрес, по которому
открыта страница. Отдельно этот случай мы не прогоняли, вывод сделан по коду.

Другие неполадки здесь не перечислены намеренно: их мы не наблюдали и выдумывать
не стали. Раздел пополнится в `T-01` — по тому, что вылезет на прогоне `T-06`
на чистой Windows-машине.

## Что здесь проверено, а что нет

Честно, чтобы вы знали, где инструкция опирается на предположение.

**Проверено реальным прогоном (macOS, Docker 29.6.1, Compose v5.3.0):** создание `.env`,
отказ повторного `make init` перезаписывать файл, запуск с занятым портом и его
исправление через `.env`, полный запуск всех пяти контейнеров, вход по коду со
страницы писем, открытие экрана настроек, остановка и повторный запуск с сохранением
данных, запуск скриптами `sh infra/scripts/…` напрямую, без `make`.

**Проверено на релизном архиве (`X-19`):** архив распакован в пустую папку, и с шага 3
по шаг 5 инструкция пройдена именно в ней — `.env`, запуск, вход по коду. Версия,
которую показывает `/api/v1/version`, совпала с именем архива. Проверка шла на macOS;
номера портов при этом были другими, потому что на машине уже работала другая копия.

**Не проверено:**

- **Всё, что относится к Windows** — установка Docker Desktop с WSL2, работа Git Bash,
  файлы `start.bat` и `stop.bat`. Эти места помечены в тексте плашкой.
- **Пометка «скачано из интернета» и SmartScreen** на шаге 2. Windows-машины у нас нет;
  нужен ли шаг «Разблокировать», выяснит `T-06`.
- **Время первого запуска на чистой машине.** У нас образы уже были скачаны, а сборка
  бралась из кэша. На Windows вдобавок медленнее ставятся зависимости веб-части — из-за
  того, как Docker пробрасывает файлы проекта внутрь контейнера.
- **Сохранение настроек** на экране «Настройки»: экран открывали, значения не меняли.
