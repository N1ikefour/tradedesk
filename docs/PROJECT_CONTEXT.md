## Продукт

**TradeDesk** — журнал сделок трейдера с автоматической синхронизацией из MetaTrader 5. Открыл браузер — увидел все свои сделки, свежие, без ручных действий, с базовой статистикой и структурированной рефлексией по каждой сделке.

Ориентир по функционалу — HybridTrader (dash.hybridtrader.ai). Сначала для себя, затем рынок СНГ (`PLAN.md` §1).

Единица журнала — **позиция**, собранная из `deals`. Deals неизменяемы. Пользовательский слой (заметки, теги, рефлексии) хранится отдельно и не затирается пересборкой.

## Риски, за которыми следим

Полная карта — `PLAN.md` §6. Здесь то, что влияет на ближайшие задачи:

1. **Сборщик позиций — главный технический риск.** Хеджинг/неттинг, частичные закрытия, свопы, перекрывающиеся батчи. Митигация: `S1-03` с 8 фикстурами и тестом идемпотентности до того, как на него ляжет UI. Домен вынесен в skill `ingest-mt5`.
2. **`MASTER_KEY` после backfill не меняется и не теряется** — иначе credentials нечитаемы. Проговаривается при каждом касании `S0-05`.
3. **Коллектор нельзя проверить на машине разработки.** macOS/Linux не запускают `MetaTrader5`. Верификация задач `S1-08…S1-11` — руками принципала на Windows. Агент не имеет права писать «проверено», не имея прогона.
4. **Аудит доступа к credentials заявлен в `PLAN.md` §6, но механики в `SPEC.md` нет.** Открытый вопрос — решить до `S0-05`: нужна ли таблица аудита обращений `/internal/collector/assignments`, или достаточно структурных логов без значений.
4a. **Python 3.12 на машине разработки отсутствует** (есть 3.14). Локальные прогоны идут не на целевой версии; авторитетная проверка — CI. Пока приложения пустые, риск низкий; после S0-02 расхождение может начать кусаться.
5. **Открытые вопросы `PLAN.md` §8** (брокеры для тестов, хеджинг/неттинг у нас, Windows-VPS, домен для OTP, словарь рефлексии) — решить до этапа 1. На этап 0 не влияют.
6. **`SPEC.md` §14** содержит значения по умолчанию для нерешённого. Они действуют, пока не решено иначе явно.
