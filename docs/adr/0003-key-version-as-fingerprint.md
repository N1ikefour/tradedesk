# ADR-0003: `key_version` — отпечаток ключа, а не счётчик оператора
Дата: 2026-09-04. Статус: accepted.

## Контекст

`SPEC.md` §3.2 задаёт в таблице `account_credentials` колонку `key_version smallint not null default 1` — «версия мастер-ключа, которым завёрнут ключ данных».

Первая реализация (`S0-05`) сделала это буквально: номер задаёт оператор переменной окружения `MASTER_KEY_VERSION`, ротация поднимает его на единицу.

Ревью нашло, что такая конструкция допускает **необратимую потерю паролей брокерских счетов**, и воспроизвело это на живой базе.

Механика: ротация выбирает строки условием `key_version <> target`. Расшифровка при этом перебирает текущий и предыдущий ключ, чтобы пережить момент миграции. Значит строка, у которой **колонка равна целевой версии, а обёртка сделана предыдущим ключом**, не выбирается ротацией вообще. Скрипт печатает «Осталось: 0» и разрешает убрать предыдущий ключ из окружения — после чего строка мертва.

В такое состояние строка попадает от обычной операторской ошибки: человек поднял номер в `.env`, не запустив ротацию, или запустил шаги не в том порядке.

Отдельная ирония: расхождение колонки с реальностью — ровно тот случай, ради которого в расшифровку добавлен перебор ключей. Читающий слой ошибку молча переживает, а ротация превращает её в потерю.

## Варианты

1. **Оставить счётчик, добавить верифицирующий проход.** Перед словом «готово» скрипт читает все строки только текущим ключом и падает, если хоть одна не открылась. Дёшево, схема и спека не меняются. Минус: возможность ошибиться остаётся, тихая потеря превращается в громкое падение, и в инструкции для тестировщика появляется лишняя переменная, смысл которой ему объяснять незачем.
2. **Вывести значение колонки из самого ключа** — короткий отпечаток материала. Один и тот же ключ всегда даёт одно и то же значение, поэтому колонка **физически не может разойтись с реальностью**. Переменная `MASTER_KEY_VERSION` не нужна. Минус: меняется смысл поля, описанного в `SPEC.md` §3.2.
3. **Оба сразу.**

## Решение

Вариант 3. Утвердил принципал 2026-09-04.

`key_version` хранит короткий отпечаток мастер-ключа, выведенный из его материала. Переменная `MASTER_KEY_VERSION` удаляется. Скрипт ротации дополнительно верифицирует читаемость всех строк текущим ключом, прежде чем разрешить убрать предыдущий.

Отпечаток закрывает известную причину расхождения по построению; верификация ловит неизвестные.

**Момент выбран сознательно: зашифрованных данных в проекте ноль.** Позже смена смысла колонки означала бы миграцию по шифрованным строкам — то есть ровно ту операцию, безопасность которой и обсуждается.

## Последствия

- `SPEC.md` §3.2 обновлена: колонка описана как отпечаток, а не порядковый номер. Тип и имя не меняются — миграции не требуется.
- В `.env.example` и в инструкции для тестировщика на одну переменную меньше.
- Коллизия отпечатков текущего и предыдущего ключа обязана давать внятный отказ **до** начала ротации.
- Верифицирующий проход стоит одну расшифровку на строку за прогон — на масштабах v1 несущественно.
- Пересмотреть, если ключей станет много одновременно (несколько инсталляций с общей базой) — тогда короткого отпечатка может не хватить.
