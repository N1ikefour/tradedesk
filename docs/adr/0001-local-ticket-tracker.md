# ADR-0001: локальный трекер задач вместо Linear
Дата: 2026-09-03. Статус: accepted.

## Контекст

`DEVELOPER_MANUAL.md` §8 построен вокруг внешнего трекера (у нас — Linear): статусы, анатомия тикета, авторитетный комментарий-итог. Linear-workspace доступен (команда Totti, префикс `TOT`), но у принципала исчерпан лимит задач на тарифе — завести 38 тикетов этапов 0–2 туда нельзя.

При этом бэклог уже существует: `SPEC.md` §12 содержит все 38 задач с ID и Definition of Done. Дублировать их во внешний трекер пришлось бы вручную и поддерживать в двух местах.

## Варианты

1. **Linear** — процесс мануала работает дословно. Минус: упирается в лимит тарифа; требует оплаты или чистки чужих проектов.
2. **GitHub Issues** — рядом с кодом, без второй системы, лимитов нет. Минус: слабее по зависимостям и статусам; всё равно дублирует `SPEC.md` §12; тикеты недоступны в оффлайне и не версионируются вместе с кодом.
3. **Локальный трекер в репозитории** — доска в markdown + файл на тикет, взятый в работу. Минус: нет напоминаний, нет нотификаций, статус легко забыть обновить; дисциплина держится только на оркестраторе.

## Решение

Вариант 3. Бэклог остаётся в `SPEC.md` §12 и не дублируется. `docs/tickets/BOARD.md` — доска статусов. `docs/tickets/<ID>.md` заводится в момент взятия задачи в работу и содержит только дельту над `SPEC.md`: статус, ветку, PR, развилки, решения, итог.

ID берутся из `SPEC.md` §12 (`S0-01`, `S1-04`, `T-02`); второй нумерации нет. Задачи вне спеки получают ID `X-NN`.

Утвердил принципал 2026-09-03.

## Последствия

- Работает: статусы, анатомия тикета, авторитетный итог (§8.5 мануала переезжает в раздел `## Итог` файла тикета), связь тикет ↔ ветка ↔ PR.
- Теряем: напоминания, нотификации, автоматические переходы статусов от git-событий, взгляд «сверху» на загрузку.
- **Главный риск — рассинхрон доски и реальности.** Митигация: статус меняется одним движением в двух местах (`BOARD.md` + шапка тикета) в том же коммите, что и работа; перед взятием новой задачи оркестратор сверяет `BOARD.md` с `git branch` и открытыми PR.
- Пересмотреть, когда: появится второй участник, или лимит Linear перестанет быть проблемой, или доска начнёт систематически расходиться с реальностью.
