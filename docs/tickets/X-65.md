⚠️ **Найдено на живой машине первого пользователя**, 10 сентября 2026. Крупнейшая находка первого прогона: на этом месте установка встала примерно на час.

## Что обещает инструкция

`SETUP.md` §1, блок «На Windows не проверено», пункт 1:

> **Docker Desktop for Windows** требует включённого **WSL2**. Установщик Docker предлагает его включить сам; после этого нужна перезагрузка.

Одна строка, одно действие, одна перезагрузка.

## Что произошло на самом деле

Windows 10 22H2 (19045.6332), Docker Desktop 29.7.2, установка per-user. Установщик Docker **ничего не предложил и ничего не включил**. После установки и перезагрузки Docker показал:

```
Virtualization support not detected
Docker Desktop failed to start because virtualization support wasn't detected.
```
— и `Engine stopped`, при том что в диспетчере задач **«Виртуализация: Включено»**, то есть на уровне процессора всё было в порядке с самого начала.

`wsl --status` отвечал **пустотой** — команда есть, состояния нет.

`wsl --install` упал: **«не удаётся установить связь с сервером»**. Машина в России, Microsoft недоступен без VPN.

**Сработала такая последовательность:**

1. `dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart`
2. `dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart`
   — обе локальные, сеть не нужна;
3. перезагрузка;
4. после неё Docker сменил ошибку на **«WSL needs updating… run `wsl --update`»** и `Engine starting` — то есть первые два шага сняли основную проблему;
5. `wsl --update` **с включённым VPN** — единственный шаг, которому сеть действительно нужна;
6. кнопка **Try Again** в окне Docker, без перезагрузки.

## Почему это важнее остальных находок прогона

Это **не наш код**, и почини мы всё остальное — здесь встанет каждый следующий человек. Причём встанет на сообщении, которое уводит не туда: Docker говорит «виртуализация не обнаружена», человек лезет в BIOS, а в BIOS всё правильно и было. Мы сами сначала отправили туда же.

Отдельно: **два из шести шагов требуют VPN**, и об этом в инструкции нет ни слова, хотя целевая машина в России. Для человека, у которого VPN нет, установка непроходима, и он этого не поймёт.

## Что сделать

1. **Развернуть §1 в настоящую последовательность** — шесть шагов выше, с проверкой после каждого. Первым делом `dism`, а не `wsl --install`: он локальный и снимает 80 % проблемы.
2. **Написать, что Microsoft может быть недоступен и что делать.** Явно: какие шаги ходят в сеть, что `wsl --install`/`wsl --update` идут мимо системного прокси, и что браузером с `https://aka.ms/wsl2kernel` качается то же самое, когда команда не может.
3. **Дать диагностику, разводящую два случая**, чтобы не отправлять человека в BIOS зря: диспетчер задач → «Виртуализация». `Отключено` — BIOS; `Включено` — компоненты Windows.
4. **Добавить `wsl --status` в проверки шага 1** рядом с `docker --version`: пустой ответ = WSL не установлен.
5. Проверить, права ли строка «установщик Docker предлагает включить сам» хоть для какой-то версии — на 29.7.2 она неверна. Скорее всего просто убрать.

## Acceptance criteria

- §1 доводит от чистой Windows до `Engine running` без внешних подсказок.
- Сказано, какие шаги требуют сети и что делать, если её нет.
- Ни один шаг не отправляет в BIOS человека, у которого виртуализация уже включена.
- Блок 0 `docs/collector-windows-checklist.md` получает шаг «Docker поднялся» до всего остального.
- ⚠️ Проверить по-настоящему можно только на чистой Windows — сказать явно.
