## Контекст

Первая задача проекта. В репозитории нет ни одного приложения — только документы и каркас процесса. От этого тикета зависит всё остальное: `make lint` и `make test` — команды, которыми проверяются все последующие задачи, а CI — гейт перед каждым мержем.

Структура — `SPEC.md` §2.1, конвенции — §2.2, разрешённые зависимости — §2.3.

## ⚠️ Семантика / развилки

Решения приняты оркестратором до старта, чтобы агент не выбирал молча. Если какое-то мешает — эскалация, а не обход.

**1. Makefile содержит все команды из `CLAUDE.md` §4, но работают только `lint`, `test`, `help`.**
`init`, `up`, `down`, `migrate`, `revision`, `types` — заглушки, печатающие «реализуется в S0-06 / S0-02 / S0-03» и выходящие с ненулевым кодом. Причина: список команд задокументирован и им будут пользоваться; `make up`, падающий с «No rule to make target», хуже осмысленного сообщения. Реализуются в своих задачах.

**2. Приложения создаются пустыми — ровно настолько, чтобы CI был зелёным.**
- `apps/api`: `pyproject.toml`, пакет `app/` с `__init__.py`, `tests/` с одним тривиальным тестом (pytest без тестов выходит с кодом 5 и красит CI). **`main.py`, config, БД — это S0-02, здесь их нет.**
- `apps/web`: `package.json`, `vite.config.ts`, `tsconfig.json` (strict), eslint + prettier, `index.html`, минимальный `src/main.tsx`, рендерящий заглушку. **Роутер, layout, тема, генерация типов — это S0-07, здесь их нет.**
- `apps/collector-mt5`: `pyproject.toml`, пакет `collector/` с `__init__.py`, `collector.env.example` по `SPEC.md` §8.1. **Код коллектора — S1-08.**
- `packages/shared-schemas/`, `packages/mql5-ea/`, `infra/` — директории с `.gitkeep`. Содержимое — S1-01, этап 4, S0-06/T-02.

**3. Runtime-зависимости в `pyproject.toml` не объявляются — только dev-инструменты** (ruff, mypy, pytest, pytest-asyncio). Причина: fastapi/sqlalchemy/alembic нужны с S0-02, а объявленные, но неиспользуемые зависимости замедляют CI и создают иллюзию, что каркас приложения есть. Объявляются в задаче, которая их первой использует, из списка `SPEC.md` §2.3.

**4. ⚠️ `MetaTrader5` НЕ попадает в основные зависимости коллектора.** Пакет существует только под Windows — на Linux-раннере CI установка упадёт. Вынести в optional-dependencies (extras) или обусловить маркером окружения `sys_platform == 'win32'`. Это самая вероятная причина красного CI в этом тикете.

**5. `mypy --strict` настраивается сразу для `domains/ingest` и `domains/analytics`** (`SPEC.md` §2.2), хотя этих модулей ещё нет — через overrides в конфиге. Причина: настройка, отложенная «на потом», не появляется никогда.

**6. Pre-commit обязан включать `detect-private-key`** и проверку, что `.env` не коммитится. Секреты в истории — необратимая проблема (`DEVELOPER_MANUAL.md` §11.1).

## Acceptance criteria

Сверх DoD спеки («CI зелёный на пустых приложениях»):

- `make lint` и `make test` проходят локально и в CI, и это **одни и те же команды** — расхождение локального и CI-прогона считается багом инфраструктуры.
- CI состоит из двух независимых джобов: `api` (ruff + mypy + pytest на Python 3.12) и `web` (eslint + prettier --check + tsc + vite build на Node 20+). Триггеры: `push` в `main` и `pull_request`.
- `make help` печатает список команд с пояснением, какие ещё не реализованы.
- Ни один секрет и ни один `.env` не попадает в дифф.
- `git status` чист после прогона всех команд: артефакты сборки и кэши покрыты `.gitignore`.

## Зависимости

Ничего не блокирует — первая задача. Блокирует все остальные.

## ⚠️ Ограничение верификации на машине разработки

Проверено оркестратором 2026-09-03 на машине принципала (macOS):

| Инструмент | Состояние |
|---|---|
| Python 3.12 | **отсутствует** (есть только 3.14) |
| `uv`, `pyenv`, `poetry`, `pipx`, `pre-commit` | **отсутствуют** |
| Docker daemon | **не запущен** |
| Node v22.23.1, npm, npx | есть |

Следствия для этого тикета:

- Python-инструменты ставятся в локальный venv на **3.14**, а не на целевой 3.12. Локальный зелёный прогон — не доказательство зелёного CI. **Авторитетный прогон — GitHub Actions на 3.12.**
- `pre-commit` ставится в тот же venv; его хуки прогоняются командой, а не через git-хук.
- Docker в этом тикете не нужен.
- В итоге обязательно разделить: что проверено локально (и на какой версии Python), что проверено в CI, что не проверялось.

## Итог (оркестратор) — готово к ревью/мержу

Реализовано, отревьюено независимым ревьюером — вердикт **approve** после закрытия находок. PR: https://github.com/N1ikefour/tradedesk/pull/1

### Что сделано

25 файлов, три коммита: скелет → фиксы ревью → docs.

- **Структура** `SPEC.md` §2.1 в разрешённой тикетом части. Приложения пустые: `apps/api` (пакет + один тест), `apps/web` (заглушка), `apps/collector-mt5` (пакет + `collector.env.example`, сверен с §8.1 построчно). `packages/`, `infra/` — `.gitkeep`.
- **Makefile.** Работают `install`, `hooks`, `ci`, `lint`, `test`, `build-web`, `format`, `help`. Заглушки `init`/`up`/`down`/`migrate`/`revision`/`types` печатают задачу, в которой появятся, и падают с кодом 2.
- **CI** — два джоба: `api` (Python 3.12: ruff, mypy, pre-commit, pytest) и `web` (Node 22: eslint, prettier, tsc, vite build). Оба вызывают `make ci-api` / `make ci-web` — состав проверок задан только в Makefile, в workflow его нет.
- **Миграций нет. Runtime-зависимостей нет** — придут в S0-02 с первым кодом. Объявлены только dev-инструменты.

### Дизайн-развилка

- **`MetaTrader5` вне основных зависимостей коллектора** — extra с маркером `sys_platform == 'win32'`. Пакет существует только под Windows и уронил бы Linux-раннер. Подтверждено `pip install --dry-run` на darwin: пакет не резолвится.
- **`mypy --strict` для `domains/ingest` и `domains/analytics` выражен явным списком из 12 флагов, а не через `strict = true`.** Развилка 5 этого тикета заказывала механизм, которого в mypy нет: `strict = true` внутри `[[tool.mypy.overrides]]` применяется ко всему проекту **без единого предупреждения**, rc=0. Ошибка постановки моя, не автора. Проверено A/B: идентичные файлы внутри доменов дают 3 ошибки, вне доменов — `Success`; контрольный `mypy --strict` на том же файле даёт ровно тот же набор.
- **Локальный гейт — `make ci`, а не `make lint && make test`.** Второе не проверяет сборку web, на которой гейтится CI, то есть документированный гейт был подмножеством удалённого — ровно то расхождение, которое AC называет багом инфраструктуры. `CLAUDE.md` §4 и §6 приведены в соответствие.
- **`pre-commit` гоняется в CI.** До этого `detect-private-key` и запрет `.env` защищали только того, кто выполнил `make hooks`. `DEVELOPER_MANUAL.md` §11.1 называет секрет в истории необратимой проблемой.
- **RUF001 включён, RUF002/RUF003 заглушены.** Гомоглиф в строковом литерале — потенциальный баг данных (тикеры, коды ошибок), гомоглиф в русской прозе комментария — шум.
- **Кэш `~/.cache/pre-commit` не добавлен вопреки рекомендации ревьюера.** Он оценил цену в +20–45 с; измерение показало обратное: джоб `api` 33 с без pre-commit → 31 с с ним. Кэш решал бы несуществующую проблему. Кандидат в тикет, если время вырастет.
- **Node 22, а не 20:** vite 8 объявляет `engines: ^20.19 || >=22.12`.
- **Инструментальные npm-пакеты** (`typescript-eslint`, `@eslint/js`, `globals`, `@types/node`, `@vitejs/plugin-react`) отсутствовали в `SPEC.md` §2.3. Согласовано с принципалом → `SPEC.md` v1.1, оговорка про тулинг.

### Тесты / проверки

**Авторитетно — CI на GitHub, Python 3.12.** Три прогона, все зелёные:

| Прогон | Коммит | api | web |
|---|---|---|---|
| 33752897900 | скелет | success 33 с | success 15 с |
| 33754538490 | + фиксы ревью | success 31 с | success 15 с |
| 33755661058 | + docs | success | success |

Подтверждено чтением лога, что `pre-commit run --all-files` в CI реально исполняется (ставит окружения хуков), а не пропускается.

**Локально — на Python 3.14.6, не на целевой 3.12** (3.12 на машине нет). Автором и независимо ревьюером: `make ci` rc=0; все 11 целей rc=0; шесть заглушек rc=2; `pre-commit run --all-files` зелёный; `git status` чист.

**Ревью.** Первый проход — needs-changes: 1 major (протечка mypy strict), 6 minor, 4 nit. Все закрыты, переповерка — **approve**, регрессий не найдено.

Тест один и тривиальный — это осознанно: продуктового кода в задаче нет, покрывать нечего. Ревьюер подтвердил, что каркас готов принимать реальные тесты (`tests/unit` и `tests/integration` разделены, `tests/fixtures` есть, `asyncio_mode = "auto"`).

**Поправка ревьюера к отчёту автора, важная на будущее:** mypy на global-only флаге в per-module секции **не падает** — печатает предупреждение в stderr и возвращает rc=0. Метод отсева автора сработал, но флаг, дописанный туда впредь, будет молча проигнорирован при зелёном CI.

### Не проверялось / follow-up

**Не проверялось:**

- Прогон на Python 3.12 локально — нечем, `python3.12`/`uv`/`pyenv` на машине отсутствуют. Компенсируется зелёным CI.
- `make install` и `make hooks` с нуля — оба агента работали в готовом окружении. **`make install` не исполняется ни одним джобом CI, поэтому его поломку не поймает никто.**
- Windows-путь целиком: `pip install -e .[mt5]`, реальная установка `MetaTrader5`, `collector.env`. Только маркер на darwin.
- Состав `--strict` сверен для mypy 1.20.2; диапазон в конфиге `>=1.11,<2.0`. При апгрейде mypy явный список может отстать от нового strict-флага молча.
- Прогоны однократные, flaky не искали.

**Follow-up — кандидаты в тикеты `X-NN`, ни один не блокирует мерж:**

1. Пины версий dev-инструментов вместо диапазонов — новый релиз ruff/eslint может покрасить CI без коммита в код. Делать после того, как известны версии, реально прошедшие CI на 3.12.
2. `pre-commit>=3.5,<5` продублирован в `Makefile` и `ci.yml` — перенести в `apps/api[dev]`. Естественно ложится в **S0-02**, где и так правится этот `pyproject.toml`.
3. `ignore_missing_imports = true` глобально в `apps/api` — сузить до per-module, когда появятся настоящие зависимости. **S0-02.**
4. Нет `conftest.py` и разделения запуска unit/integration — когда в `tests/integration/` появятся testcontainers, быстрый локальный прогон станет невозможен. **S0-02/S0-04.**
5. Нет `pytest-cov` и порога 90 % для `ingest`/`analytics` (`SPEC.md` §13) — мерить пока нечего.
6. Нигде не задокументировано, что на Windows коллектор ставится с extra `[mt5]` — знание живёт только в комментарии `pyproject.toml`. **S1-10.**
7. `rev:` хуков pre-commit — теги, не SHA. Сдвинутый тег меняет поведение молча.

**Закрыто в ходе задачи, не переносится:** guard тестовой БД внесён в DoD S0-02 (`SPEC.md` v1.1) — требование жило в §13 и `CLAUDE.md`, но отсутствовало в DoD задачи, где должно появиться.

Мерж — за тобой. Деплоя в этой задаче нет: прода не существует.
