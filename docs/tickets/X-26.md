Задачи нет в `SPEC.md` §12 — описание полное по `DEVELOPER_MANUAL.md` §8.3.

## Что происходит

Проба ревьюера `S1-05`: коллектор `old-machine` забрал счёт. Дальше пользователь делает **всё, что ему доступно** — `pause`, `resume`, `PATCH` со сменой пароля, — а `collector_id` в базе остаётся `old-machine`. Новый коллектор `new-machine` получает пустой список.

Единственный выход — удалить счёт и завести заново, **потеряв все сделки**.

## Почему это дыра в спеке, а не отступление от неё

`SPEC.md` §5.6 описывает только закрепление: «При выдаче `collector_id` фиксируется за счётом». Про освобождение там **нет ничего**. Поэтому `S1-05` и не решал этот вопрос — решать его значило бы придумать правило, которого в спеке нет.

Сценарий не экзотический: человек переставил Windows, сменил ноутбук, переустановил коллектор с другим `collector_id`. Для целевого пользователя это выглядит как «журнал сломался и чинится только удалением счетов».

## Решение принципала: отложено

**5 сентября 2026.** Друг запускает коллектор на одной машине — сценарий переезда возникнет нескоро, и городить механизм под него сейчас незачем.

**Когда возвращаться:** при первой смене машины у друга, при появлении второго пользователя, либо при выносе приложения на сервер.

**Что при этом помнить:** вставка сделок идемпотентна по устройству (`SPEC.md` §5.3, `ON CONFLICT DO NOTHING`), поэтому две машины на одном счёте не создадут дублей — только лишнюю работу. То есть закрепление защищает от напрасной работы, а стоит потери всей истории. Цена несопоставима, и это главный довод при возврате к задаче.

**Рекомендация на тот момент** (не решение): освобождать по молчанию тем же `check_collectors`, который уже ходит раз в минуту, — второй порог около часа. Человек ничего не делает и ни о чём не знает; система самовосстанавливается, если машина вернётся.

## Развилки — решать принципалу

Освобождать при смене credentials (`PATCH` с новым паролем — явный признак переезда)? При `resume`? Отдельной ручкой «отвязать коллектор»? По молчанию N часов автоматически?

У каждого своя цена. Автоматическое освобождение по молчанию рискует перебросить счёт на другую машину, пока первая просто выключена на ночь. Ручка требует UI и объяснения понятия, которого пользователь не знает.

**Начинать надо с вопроса «как человек об этом узнает»**, а не с механизма: сейчас он видит пустой экран без объяснения.

## Acceptance criteria

- Решение зафиксировано в `SPEC.md` §5.6 — это дополнение контракта, а не правка кода.
- Пользователь, переставивший коллектор, восстанавливает работу **без потери сделок**.
- Тест на сценарий переезда: старый `collector_id` → новый, счета выданы новому.
