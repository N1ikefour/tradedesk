Найдено ревью `T-02`, поймано живьём. Дефект `S0-06`, не той задачи, где нашёлся.

## Суть

`infra/scripts/start.sh:78-79`:

```sh
{ docker compose --profile "$PROFILE" up -d --build 2>&1; echo "$?" >"$STATUS_FILE"; } | tee "$LOG"
```

Под `set -e` падение `docker compose` убивает подоболочку **до** `echo`, файл со статусом остаётся пустым, и человек видит:

```
docker compose up завершился с кодом  — окружение не поднято
```

Дыра вместо числа ровно в тот момент, когда число нужнее всего.

Комментарий рядом объясняет, зачем статус уносится отдельным файлом (`tee` всегда возвращает 0), — то есть проблему автор видел, но закрыл наполовину.

## Почему это стоит починить

`make up` — вторая команда, которую выполняет человек при установке, и первая, которая может упасть. Инструкция (`SETUP.md`) в разделе «Если что-то не так» разбирает случаи по коду выхода; без кода человеку нечего искать и нечего прислать нам.

От той же ловушки автор `T-02` защитился в своём `backup.sh` через `set +e` вокруг конвейера — приём в проекте уже есть, просто не применён здесь.

## Что сделать

Снять `set -e` вокруг конвейера (как в `backup.sh:91-98`), либо использовать `PIPESTATUS`, либо разделить: сначала выполнить, потом писать лог.

Проверять — прогоном с заведомо падающим compose (занятый порт, битый `docker-compose.yml`): в выводе обязано стоять число.

Заодно посмотреть, нет ли той же формы в `stop.sh` и `ci-target.sh`.
