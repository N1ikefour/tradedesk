Найдено ревью `S2-06`, воспроизведено на живом стеке.

## Суть

Нулевой байт в текстовом query-параметре `GET /journal/positions` доезжает до Postgres и роняет запрос. Наружу уходит `500 internal_error`:

```
GET /journal/positions?...&symbol=%00%00EURUSD  -> HTTP 500
GET /journal/positions?...&q=%00abc             -> HTTP 500
GET /journal/positions?...&tags=%00tag          -> HTTP 500
GET /journal/positions?...&symbol=%01EURUSD     -> HTTP 200   (виноват именно NUL)
GET /journal/positions?...&symbol=ZZEURUSD      -> HTTP 200
```

Домен — `S2-01` (уже влит). Клиентскую половину чинит `S2-06`: экран перестаёт такое отправлять. **Это не закрывает дефект** — ссылку формирует кто угодно, а не только наш экран.

## Почему это тикет, а не мелочь

`500` здесь означает три вещи сразу, и каждая плохая:

1. **Ответ врёт о причине.** Виноват запрос, а не сервер; человек, получивший такую ссылку, видит «у них всё сломалось».
2. **Валидация на границе не сработала**, хотя `CLAUDE.md` §5 требует её ровно там: «валидация на границе API один раз, pydantic v2». Управляющий символ прошёл границу и был пойман базой.
3. **Это дешёвый способ насорить в логах и в Sentry** чужими стектрейсами: один GET без тела, повторяемый сколько угодно — лимита на этот маршрут нет (ср. `X-27`).

Ни один из 1295 тестов api этого не ловит.

## Что сделать

Отбивать управляющие символы **на границе**, в pydantic-модели `PositionsQuery`, а не в SQL и не на фронте. Ответ — `400 validation_error` с полем в `details.fields`, как у остальных нарушений формы.

Развилки, которые надо решить явно:

1. **Какой класс символов запрещать.** Только нулевой байт или весь класс `Cc`/`Cf`? В проекте уже есть прецеденты: `core/text.py` (скраб внешнего текста) и схемы accounts. **Правило должно быть одно**, а не третье по счёту.
2. **Отбрасывать или отвергать.** Тихо вырезать — значит искать не то, что просили, и не сказать об этом. Отвергать — значит `400` на ссылку, которая почти правильная. Ревью `S2-06` отдельно отметило родственную беду: подрезание фильтров на клиенте молча **расширяет** выборку.
3. **Где ещё та же дыра.** `GET /journal/positions` — не единственный маршрут с текстовым query-параметром. Проверить все, а не только найденный.

Тест обязателен, и мутационно: убрать проверку — тест должен покраснеть на `500`.
