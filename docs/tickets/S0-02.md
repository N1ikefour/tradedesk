## Контекст

Первый продуктовый код проекта. `S0-01` смержен (`1ee066d`): структура есть, `make ci` работает, CI зелёный, приложения пустые. `apps/api` сейчас — пакет `app/` с `__init__.py` и один тривиальный тест.

Контракт из `SPEC.md` §5.7 дословно:

```
GET /api/v1/health   → {status, db, redis, version}
GET /api/v1/version  → версия приложения
```

Формат ошибок — `SPEC.md` §5.1: `{"error": {"code": "snake_case", "message": "по-русски", "details": {}}}`. Коды: 400 (`validation_error`, `details.fields`), 401, 403, 404, 409, 422, 429.

Переменные окружения — `.env.example` и `SPEC.md` §11.2. Ничего не выдумывать: если переменной там нет, её нет.

## ⚠️ Семантика / развилки

Решения приняты оркестратором до старта. Мешает — эскалация, не обход.

**1. Alembic настраивается, но ни одной ревизии не создаётся.** Таблицы раздела 3 — это `S0-03`. Здесь: `alembic.ini`, `env.py` с async-движком, `script.py.mako`, пустая история. `make migrate` и `make revision` перестают быть заглушками и начинают работать по-настоящему.

**2. Guard тестовой БД — в DoD (`SPEC.md` v1.1).** Требование `SPEC.md` §13 и `CLAUDE.md` §6: имя БД обязано содержать `_test`, исключение бросается **до первого запроса**. Нужен тест, доказывающий, что на не-тестовом URL guard срабатывает — а не только что на тестовом не срабатывает.

**3. ⚠️ env-guard для прода — сверх DoD спеки, добавляю осознанно.** `DEVELOPER_MANUAL.md` §11.2 требует: приложение отказывается стартовать в проде со значениями по умолчанию для секретов. Config пишется именно в этой задаче; второй проход по нему позже дороже (§1.6 «фундамент раньше фич»). Объём: в `APP_ENV=prod` пустые или дефолтные `SECRET_KEY`, `MASTER_KEY`, `OTP_PEPPER`, `COLLECTOR_TOKEN` → отказ старта с внятным сообщением, называющим переменную. В `APP_ENV=local` — не мешать разработке.

**4. `/health` не падает при недоступной зависимости.** Возвращает `200` с телом, где `db` или `redis` помечены как недоступные, и `status` соответственно. Не `500` и не `503`: приложение живо, деградировала зависимость (`DEVELOPER_MANUAL.md` §6.2 «мягкая деградация»). `/ready` **не заводим** — в `SPEC.md` §5.7 его нет; если внешний мониторинг потребует отдельный readiness, это будет решение с ADR, а не догадка агента.

**5. Sentry — только по DSN.** Пустой `SENTRY_DSN` не ломает старт и не пишет предупреждений на каждый запрос.

**6. Никаких доменов, кроме `system`.** `auth` — `S0-04`, `accounts` — `S1-06`, `ingest` — этап 1. Каталоги домена не создавать «под будущее».

**7. Секреты не попадают в логи.** structlog настраивается так, чтобы значения `SECRET_KEY`, `MASTER_KEY`, `OTP_PEPPER`, `COLLECTOR_TOKEN`, `DATABASE_URL` (в нём пароль) не выводились ни при старте, ни в ошибках. Проверка присутствия — `present` / `MISSING`, не значение.

## Acceptance criteria

Сверх DoD спеки:

- `GET /api/v1/health` при поднятых Postgres и Redis отдаёт `200` и **реальные** статусы обеих зависимостей, а не заглушки.
- При остановленной зависимости `/health` отдаёт `200` с пометкой недоступности — не `500`.
- `GET /api/v1/version` отдаёт версию из окружения/манифеста.
- Любая ошибка API — в формате §5.1. Тестами покрыты минимум `404` и `validation_error` с заполненным `details.fields`.
- Логи — JSON через structlog. Ни один секрет не появляется в выводе старта и в текстах ошибок.
- Приложение стартует без `SENTRY_DSN`.
- Guard тестовой БД: исключение **до первого запроса**; тест на не-тестовом URL.
- env-guard: `APP_ENV=prod` с пустым секретом → отказ старта, сообщение называет переменную; тест.
- `alembic upgrade head` и `alembic downgrade base` отрабатывают на пустой истории.
- `make ci` зелёный. Unit-тесты проходят **без** Docker; integration отделены маркером.
- Runtime-зависимости объявлены из `SPEC.md` §2.3 и не шире.

### Что сделано

Контракт, зафиксированный для S0-07 (frontend возьмёт его дословно):

```
GET /api/v1/health  → 200 {"status": "ok"|"degraded", "db": "ok"|"unavailable",
                           "redis": "ok"|"unavailable", "version": "0.1.0"}
GET /api/v1/version → 200 {"version": "0.1.0"}
```

Ошибка — `{"error": {"code", "message", "details"}}`; 422 от FastAPI приводится к `400 validation_error` с `details.fields`. OpenAPI — `/api/v1/openapi.json`, доки `/api/v1/docs`.

- `core/config.py` — pydantic-settings; все секреты `SecretStr`, включая `DATABASE_URL` и `REDIS_URL` (в них пароль); presence-check `present`/`MISSING`; env-guard прода.
- `core/db.py` — async-движок, guard тестовой БД, маскирование пароля в URL.
- `core/logging.py` — structlog JSON; цензура по имени ключа **и скраб значений** в тексте исключений.
- `core/errors.py` — единый формат, стабильный словарь кодов, присланные значения наружу не возвращаются.
- `domains/system` — `/health` и `/version`.
- Alembic — async-env, **ни одной ревизии**; `make migrate` / `revision` / `downgrade` из заглушек стали настоящими.
- **Миграций в этой задаче нет.** Таблицы — S0-03.

### Дизайн-развилка

Ревьюер S0-01 советовал включить его везде, исходя из того, что русских строк в Python быть не должно; для API это неверно — `SPEC.md` §5.1 требует русские сообщения в коде. В коллекторе правило нужно: он разбирает символы брокера. Ревьюер S0-02 довод принял.
- Поглощены три follow-up из S0-01: `pre-commit` переехал в `apps/api[dev]`, `ignore_missing_imports` сужен до `testcontainers`, заведён `conftest.py` с разделением unit/integration.

### Тесты / проверки

**28 тестов** (в начале ревью было 20), из них 2 интеграционных на настоящих Postgres и Redis через testcontainers.

| Проверка | Результат |
|---|---|
| CI на GitHub, Python 3.12 | **оба джоба success** |
| Целевой Python 3.12.14 в контейнере | ruff OK, format OK, mypy чист по 19 файлам, 26 passed |
| `make ci` на хосте (3.14.6) | зелёный, 28 passed, 11 хуков pre-commit Passed |
| Alembic на живом Postgres | `upgrade head`, `downgrade base`, `current` — rc=0, ревизий нет |
| Вывод старта с подставными секретами | 0 совпадений, только `present`/`MISSING` |
| Порядок тестов | обратный, по файлу на процесс, ×3 подряд — стабильно |

**Ревью нашло blocker, который я сам себе не нашёл.** `ensure_test_database` была определена и покрыта шестью тестами, но **не вызывалась ниоткуда** — сьют молча подключался к базе `tradedesk_prod` и выполнял запрос. Риск не гипотетический: конфиг читает `.env` из корня репозитория, а фикстура `DATABASE_URL` не переопределяла, поэтому у разработчика с настоящим `.env` тесты пошли бы в рабочую базу. Guard поставлен на путь создания движка; ревьюер перепроверил двумя способами, включая проверку, что новый регрессионный тест не самоподтверждающийся.

**Второй major — тоже находка ревью.** `format_exc_info` рендерит traceback в поле `exception`, а цензор фильтровал только по имени ключа: пароль из DSN уходил в лог через текст исключения. Отдельно ревьюер отметил, что убрать `exc_info` недостаточно — Starlette после обработчика делает `raise exc`, и uvicorn логирует тот же traceback повторно. Добавлен процессор, чистящий значения; покрыт регрессионным тестом.
