## Контекст

Найдено автором `S0-04` и подтверждено ревью прогоном.

`SPEC.md` §4 требует rate-limit «10 запросов кода в час на IP». Реализация читает адрес TCP-соединения. Как только между браузером и API появляется любой посредник, все пользователи приходят с одного адреса, и лимит становится **общим на всю установку**.

Ревьюер прогнал 12 разных пользователей с одного адреса: `[202 ×10, 429, 429]`. Блокируется **одиннадцатый пользователь**, а не одиннадцатый запрос одного пользователя.

**Это ломается не только в проде за nginx.** Как только API поедет в docker-compose с published port, контейнер увидит адрес bridge-шлюза для всего трафика с хоста — то есть профиль `local` из `S0-06` тоже. У друга-тестировщика профиль именно `local`, и запросы придут в API через vite-прокси.

**Усиление, найденное ревью:** `_check_rate_limits` инкрементирует счётчик по email **до** проверки IP-лимита. Значит запросы, отбитые общим IP-лимитом, дополнительно выжигают личную квоту пользователя — 3 запроса в 10 минут. Пользователь, ничего не сделавший, теряет и общий лимит, и свой.

## Что сделать

**Прикладная часть (backend):**
- Определять адрес клиента через `X-Forwarded-For`, но **только когда запрос пришёл от доверенного прокси**. Голое чтение заголовка подделывается одной строкой и делает лимит бесполезным.
- Список доверенных источников — из переменной окружения; добавить в `.env.example`.
- Исправить порядок: проверять IP-лимит **до** инкремента счётчика по email, иначе чужие запросы жгут личную квоту.

**Инфраструктурная часть (`S0-06`):**
- Прокси обязан ставить `X-Forwarded-For` и не позволять клиенту его подделать.
- `uvicorn` запускать с `--forwarded-allow-ips`, ограниченным адресом прокси, а не `*`.
- Проверить оба профиля: `local` (vite → api) и `prod` (caddy → api).

## ⚠️ Семантика / развилки

- **Доверять заголовку без списка доверенных источников нельзя** — это не «менее строго», а полностью открытый обход. Любой клиент подставит произвольный адрес и получит свежий лимит на каждый запрос.
- **`--forwarded-allow-ips=*` — то же самое.** Значение должно быть конкретным.
- В цепочке нескольких прокси брать надо не первый и не последний элемент `X-Forwarded-For`, а первый недоверенный справа.
- Если доверенный список не настроен, безопаснее вести себя как сейчас (адрес соединения) и **громко предупреждать в логе при старте**, чем молча доверять заголовку.

## Acceptance criteria

- За прокси лимит считается по реальному адресу клиента: 12 пользователей с разных адресов через один прокси — все получают `202`.
- Подделанный `X-Forwarded-For` от недоверенного источника **не** влияет на лимит — тест.
- Отбитый IP-лимитом запрос не расходует личную квоту пользователя по email — тест.
- Проверено на реально поднятом `docker compose --profile local`, а не только `ASGITransport`.
- При ненастроенном доверенном списке приложение предупреждает в логе при старте.

## Зависимости

`S0-04` — оттуда лимит. **Блокирует любое развёртывание за прокси, включая профиль `local` у тестировщика.** Прикладную часть можно делать сразу; инфраструктурную — вместе с `S0-06`.
