Найдено на живой машине первого пользователя, при установке Python для выгрузки сделок.

## Суть

У человека, которому мы отдаём продукт, имя пользователя Windows написано кириллицей. Установщик Python это показал открытым текстом:

```
C:\Users\СОБОЛЬ\AppData\Local\Python\bin
```

Значит **все** пути по умолчанию у него не-ASCII: домашняя папка, `AppData`, venv коллектора, папка с логами, `MT5_PORTABLE_ROOT`, если он оставит значение по умолчанию.

## Почему это не мелочь

Мы разрабатываем на macOS, где такого класса ошибок не бывает вовсе. А на Windows не-ASCII путь — известный источник отказов, и все они выглядят не как «путь плохой», а как что-то другое:

- `mt5.initialize(path=…)` получает путь к портабельному терминалу; библиотека `MetaTrader5` — обёртка над нативным кодом, и её поведение на не-ASCII пути мы не проверяли ничем;
- `.bat`-файлы в кодировке консоли Windows (`cp866`) при кириллице в пути ломаются молча — не находят файл, который существует;
- `pip install -e .` в venv внутри такого пути;
- логи `logs/collector.log` и ротация;
- любая наша строка форматирования пути, попавшая в лог со скрабом.

Отдельно: длинные пути этот человек **включил** при установке Python (`Update setting now? [y/N] y`, действует после перезагрузки). У другого их может не быть, а `AppData\Local\...\portable\<account_id>` — путь не короткий.

## Что сделать

1. **Проверить весь путь установки коллектора на не-ASCII профиле.** Не «подумать, что будет», а поставить на Windows-машине с пользователем вроде `Проверка` и пройти `S1-10` целиком.
2. Решить, где мы **не** полагаемся на путь по умолчанию: возможно, `MT5_PORTABLE_ROOT` обязан быть коротким ASCII-путём вроде `C:\td-terminals` (в `SPEC.md` §8.1 он такой и есть — проверить, что установщик не заменит его на путь в профиле).
3. Явно задать кодировку у всех `.bat` и у чтения/записи файлов в коллекторе; не полагаться на кодировку консоли.
4. Ошибку «путь содержит символы, которые не поймёт терминал» показывать человеку словами, а не кодом MT5.

## Чего это стоит, если не сделать

Друг доходит до установки коллектора, она падает с сообщением про несуществующий файл, и **ни он, ни мы не понимаем почему** — потому что у нас на macOS и на CI всё зелёное. Это худший сценарий передачи: продукт не работает, а причина невидима с обеих сторон.
